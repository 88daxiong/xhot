MAS Office

每个角色都是你本机已登录的 Claude Code 或 Codex 会话。你先锁定团队设计，普通代码负责调度和工具策略；所有等人处理的事项进同一个收件箱，面板只是这份事件日志的投影。

最大亮点

不另写一套「假会话」运行时，而是把真实编码代理会话编成锁定的团队：行为签名对不上就拒绝开跑；每个工具调用只经过 decideTool 一个执法点；办公室画面由确定性归约器从追加型日志算出，不让模型去维护面板状态。

自己开多个 Claude Code / Codex 窗口时，批准、提问、卡住的角色和检查点会散落在各终端里。MAS Office 把这些等人事项收进「Needs you」，并把「谁在生产事件」和「怎么画出来」拆开：生产者只追加 mas/events.jsonl，归约器按规范生成快照，面板只读快照。源码确认

一句话输入输出：输入是已锁定的 mas/structure.json（或 .js）和一项任务；输出是追加写入的事件日志、快照，以及带出处标记、链接检查与检查者裁决的结果。运行真实团队需要你本机已安装并登录 Claude Code / Codex。

怎么用

什么情况下用

  • 要比价、行程、可行性这类调研任务分成多个角色并行做，并且希望工具批准和检查点出现在同一个收件箱。
  • 已经在用 Claude Code / Codex，想让每个角色带着自己的工具策略跑，而不是再包一层新的代理框架。
  • 只想先看办公室怎么动：npx mas-office demo 不需要登录，用模拟团队即可。

什么情况下不用

  • 没有（或不想在这台机器登录）Claude Code / Codex。真实团队路径依赖你自己的会话。
  • 需要现在就接管角色的原始终端，或要评测集上的质量数字。作者写明这些尚未完成，且暂无评测跑数。
  • 不能接受「文件传输每项目一个写者进程」、或 Codex 沙箱对读范围的已知缺口。

最小上手方案

README 给出的真实团队入口（Node ≥ 18.14，分析提交 v0.3.0）。工作区不要放在会加载到无关 CLAUDE.md 的父目录下：

mkdir ~/mas-work && cd ~/mas-work
npm install mas-office mas-office-runtime
claude auth login
codex login
mkdir -p deals/mas
curl -fsSL https://raw.githubusercontent.com/weixijia/mas-office/5a768ecac2260ba4cb21c5450593ad1b7d190041/examples/price-compare/mas/structure.js -o deals/mas/structure.js
npx mas-office team check deals
npx mas-office up . --project deals --open --task "Find the best UK price for Sony WH-1000XM6 headphones"
  • 只看动画、不登录：npx mas-office demo。作者宣称
  • 工作区应放在仓库克隆之外，否则 Claude Code 会读到本仓库的 CLAUDE.md。作者宣称
  • 本文未在本机安装 CLI，也未复现作者提到的 2026-11-10 那一次端到端运行。待验证

深入

下面这些不影响先建立整体图景。需要对照源码、字段或边界时再展开。证据仍指向固定提交 5a768ec。

锁定：只对「会改变行为」的字段签名
  • signTeam 对规范化后的行为子集做规范 JSON，再计算 sha256:<hex>。标题、名字、emoji 等外观字段被排除，所以给角色改名不会打破签名。packages/node/src/team/sign.js:1–8 packages/node/src/team/sign.js:51–55 源码确认
  • 行为子集包括拓扑、预算、核查配置、Lead 与角色的工具 / 模型 / 后端、以及闸门。packages/node/src/team/sign.js:22–40
  • README 写明：未锁定或锁定后被改过的设计，运行会拒绝。作者宣称 工具表是固定词表，锁定时拒绝词表外的工具。作者宣称
decideTool：唯一执法点
  • 文件头写明：这是已编译角色的唯一执法点。allow / deny 当场回答，ask 变成收件箱请求。packages/node/src/team/decide.js:1–4 packages/node/src/team/decide.js:84–88 源码确认
  • 硬拒绝包括：凭证路径、写出项目目录、改受保护的说明 / 设置文件、命令触及本机或本地网络、未授予的 MCP 服务器、MCP 自己落盘、全库宽搜索等。packages/node/src/team/decide.js:102–136
  • 未知工具默认是否定还是提问，由 unknownTools 决定。allow 规则对路径大小写保持原样（可写集合也是），ask/deny 在匹配时忽略大小写，以避免 macOS 上 RAW/x.pdf 读到 raw/x.pdf。packages/node/src/team/decide.js:25–27 packages/node/src/team/decide.js:84–85
事件日志与归约器，而不是模型改面板
  • 架构文档把生产者和视图拆开：追加 events.jsonl，归约器按规范生成快照，面板只读快照。文件传输用临时文件再改名，避免半份快照。docs/architecture.md:1–80 源码确认
  • 同一日志里既有等人处理的请求，也有发回给智能体的命令；文档写明命令本身不改智能体状态，只有会话随后上报的事件才改。作者宣称
  • 链接健康检查由普通代码执行，不经过模型；私有与本地地址不会被抓取。作者宣称 实现见 packages/node/src/verify/url-health.js:1–40，本文未穷尽每条 URL 规则。
取舍、已知缺口与替代方案
  • 与再写一套多代理框架相比：这里直接复用你已登录的 Claude Code / Codex，换来的是必须在本机持有这些 CLI，以及把调度绑在这些会话的能力边界上。推断
  • 作者列出的缺口（README「Limits today」，视为作者宣称）：Codex 0.167.0 的沙箱不会把读范围限制在项目目录，未询问就执行的命令会在拒绝时打断回合，但快命令可能先跑完；中断回合有单元测试，但尚未对真实 Claude Code CLI 演练；重启后未完成的批准不会被重新挂上；无代码套件还不走同一套引擎；Python SDK 尚未上 PyPI。
  • 作者称 2026-11-10 做过一次真实端到端（Lead 与一名 finder 用 Claude Code，检查者用 Codex，检查者退回一次后在第 2 轮接受）。没有评测跑，因此没有答案质量数字。作者宣称 本文未复现。待验证
  • 文件传输约定每项目只有一个写者进程；多进程应改走 mas-office serve，由服务器分配 seq。源码确认 见架构文档。

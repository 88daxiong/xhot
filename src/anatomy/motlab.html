motlab：把视频写成页面，在 Chrome 里直接编码

物理本质：它不把「视频」存成时间线上的媒体文件再去渲染；它把每一场戏写成一张会按时间画图的网页，用无头 Chrome 在页内用 WebCodecs 压成码流，再在本机用 ffmpeg 做无损拼接和混音。

唯一事实来源与不可替代闭环

底牌：项目文件夹就是时间线

project.json
  fps
  scenes: [ "a.html" | { file, transition: { type, duration, ease, params } } ]
  audio:  [ { file, start, volume, from?, duration? } ]

页面契约（运行时 SSOT）:
  canvas#c, renderAt(t), ready, TOTAL, EVENTS?

输出前的物理约束:
  宽高必须为偶数（H.264 / HEVC）
  各场景画布尺寸必须相同
  各分段色彩范围必须相同
  成片帧数 / 时长必须对得上

暗逻辑：画图发生在页内，离页的只有码流

剥掉 CLI、查看器和 Skill 之后，剩下的闭环是：源码确认

  1. Agent 或人写的是普通 HTML/JS，不是专有时间线二进制。
  2. Chrome 在真实（或软件）GPU 上执行 renderAt，用 WebCodecs 编码。
  3. Node 只收编码后的字节，再用 ffmpeg 做 copy、拼接、混音和色彩标签。
  4. Skill 只负责帮你把分镜写成符合契约的页面；它不是渲染内核。

和常见替代方案的差别

做法画面如何变成视频对 Agent 的含义代价
Remotion / 传统动画工具框架自己调度帧并编码推断要学框架模型表达力强，但页面契约不同；motlab 的基准目录里有 Remotion 对照，本文未评价快慢待验证
截屏 / 逐帧导出 PNG 再 ffmpeg图像离开浏览器再压实现简单I/O 和体积都大。motlab 源码写明「帧不以图像离开 Chrome」源码确认
纯 ffmpeg / 编辑器时间线操作媒体文件不适合「用代码画运动图形」和「视频即代码」目标不同
motlab页内 WebCodecs + 本机拼接会写 canvas 页面就能出片强依赖本机 Chrome / ffmpeg / Node 24；场景页被当作受信代码源码确认

故事板：自己会演戏的分镜纸

你不是把胶片交给后期再一格格扫描，而是把每一场戏写在一张「会自己演戏的纸」上：别人只要喊「第 3.2 秒」，纸上的画布就把那一刹那画出来。

放映厅就在这台电脑里。放映员不拍照，而是在厅里直接把画面送进压片机，送出大门的只有压好的胶片卷。如果一场戏太长，就同时开几个厅，各放一段，最后把胶片接起来。两场之间的叠化不是把两卷胶片叠着放，而是单独拍一段过渡，并把正片头尾相应的格子剪掉，免得同一格出现两次。

配乐在最后按进场时间叠上去。任何一场画幅大小不一样，整部片子就不能直接接带——这是物理限制，不是口味问题。

原系统概念故事里的对应物第一性原理作用
renderAt(t) + canvas#c会按秒数演戏的分镜纸时间到画面的唯一函数，引擎不理解你的动画库
WebCodecs VideoEncoder厅内的压片机避免海量位图出进程，只移动压缩后的码流
workers + 帧区间多个放映厅各放一段用进程换吞吐，再无损接片
transition.html + head/tail单独拍摄的叠化、剪掉重叠格转场是一等公民的一段时间，而不是后期滤镜
*.part 再 rename接好带才换片盒标签失败或中断不留下看起来完整的坏文件

取舍、失效边界与最小落地

崩溃与安全边界
  • 缺 Chrome、ffmpeg/ffprobe，或 Node 低于 24，命令会失败。源码确认
  • 页面不暴露契约、画布宽高为奇数、各场景尺寸或色彩范围不一致、成片帧数对不上，都会在结束前报错。源码确认
  • 场景 HTML 被当作本机受信代码，可以做页面在浏览器里能做的事。不要拿来渲染来路不明的项目。源码确认 见 SECURITY.md。
  • Chrome 带 --enable-unsafe-swiftshader，作者限定只打开用户自己的页面。源码确认
  • 本地 HTTP 虽绑在 127.0.0.1 并做了路径约束，但仍是把项目目录提供给本机浏览器进程。源码确认
  • 硬件编码、颜色范围（GPU 与 SwiftShader 不同）和「auto 编码器」选择依赖本机探测缓存；换机器或驱程后应用 --reprobe。源码确认 具体快慢未在本机测量。待验证

最小落地建议

  1. 先装 Node 24+、本机 Chrome/Chromium、PATH 上的 ffmpeg 与 ffprobe，再按上游文档安装 @motlab/cli。用 motlab doctor 检查，不要先跑仓库里的安装脚本做实验。
  2. 从官方 example/ 看 project.json 和场景页如何暴露 renderAt，先 motlab render example 验证整条链路。待验证（本环境未实渲染）
  3. 给 Agent 用时，让它只改场景 HTML 与 project.json，把渲染交给 CLI；Skill 是写作指南，不是内核。
  4. 需要并行加速时再加 --workers；第一段会锁死编码器，避免混用硬件/软件分段。
  5. 不要把未审查的第三方 motlab 项目直接丢给引擎；把它当「会跑代码的构建工具」。

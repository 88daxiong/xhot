PyBot

用纯 Python 规则做成的聊天机器人：没有权重、不用训练。智能体群写出规则与查表，运行时每轮只做「观察 → 提议 → 仲裁 → 记账」。

最大亮点

把「聊天模型」替换成一份可检查的规则程序：小而固定的运行时负责一轮对话的状态转换，海量 if / 正则 / 查表由智能体群写成模块，仲裁器从多个提议里只放出一句。

ELIZA 一类规则机器人要靠人手加规则，覆盖面窄；现在的做法是训练权重，推理必须加载模型。PyBot 把「扩展能力」交给生成代码，把「如何选一句、如何记住」留在 bot/runtime.py:1–16。这是一份实验产物，不是通用助手替代品。源码确认

一句话输入输出：输入是一句用户文本和一份内存中的 memory 字典；输出是一句回复、胜出的模块名，以及更新后的会话记忆。

怎么用

什么情况下用

  • 想亲手检查「规则机器人」怎样选题、怎样记住刚说过的话，而不是只看模型权重。
  • 需要一个零依赖、可离线跑的小实验：只要 Python 3.8+，不用下载模型。
  • 关心智能体群如何把评测信号变成大量可运行代码，而不是直接当产品客服用。

什么情况下不用

  • 需要开放域、工具调用或长程推理——规则库会在没写过的题目上失效。
  • 不能接受数秒启动和约一秒级回复：运行时要加载整份 bot/ 包。
  • 把 README 里的胜率数字当成可部署指标。那是作者用 LLM 裁判做的对比，本文未复跑。

最小上手方案

仓库 README 给出的本地入口（分析提交，Python 3.8+，无第三方依赖）：

git clone https://github.com/huggingface/pybot
cd pybot
python -m pybot
  • 交互聊天支持 /reset、/exit；也可用 python -m pybot -p "……" 问一句就退出，或加 -v 在 stderr 打印胜出模块和耗时。pybot.py:1–9 README.md:31–71
  • 浏览器演示在 Hugging Face Space，作者称每条回复会标出产生它的模块。作者宣称
  • 本文未在本机启动聊天或复现基准。待验证

深入

下面这些不影响先建立整体图景。需要对照源码、字段或边界时再展开。证据仍指向固定提交。

固定运行时 vs 生成出来的模块
  • 真正的状态机在 bot/runtime.py:1–121：加载模块、观察、提议、仲裁、after、追加 turns。作者在文件头写明「改模块，别改这个文件」。
  • 命令行 pybot.py:1–9 只做界面；SOURCE_COMMIT = 24cbc0439e07fd015c0747ab3be6e782a42b5c5b 记录 bot/ 拷贝来源。pybot.py:19–20
  • 本分析提交中，GitHub 目录接口列出 bot/modules/ 有 110 个条目，其中包括约 309 KB 的 arbiter.py、约 1.0 MB 的 chat.py、约 746 KB 的 safety.py、约 715 KB 的 answers.py。这是目录元数据，不是行数实测。源码确认
  • README 把共享层写成 understanding / memory / knowledge / compose，并给出约 64 万行代码、55 万行测试等数字。README.md:75–93 这些体量是作者宣称。本仓库根目录的 tests/ 按 README 只覆盖命令行；本文未清点 bot/ 内是否另有测试。
记忆里有什么，权威在哪
  • 权威状态就是进程内的 memory 字典。运行时保证 memory["turns"] 只由自己追加；模块在 respond 里改的是副本，只有胜出者的副本被写回。bot/runtime.py:57–63 bot/runtime.py:101–108
  • 仲裁器文档把话题等阅读结果指向 memory["understood"]["topics"] 等字段。bot/modules/arbiter.py:12–16 这是仲裁器源码中的约定，具体读写在 bot/understanding/ 与 bot/memory/，本文未逐文件核对字段表。
  • 没有把对话持久化到磁盘的运行时逻辑：重启或 /reset 会丢掉会话。推断自命令行与 memory 只存在于本次进程。
和替代方案比，以及失效边界
  • 相对手写 ELIZA：扩展能力来自生成代码，但仲裁与记忆协议是固定的，一轮不会因某模块崩溃而中断。bot/runtime.py:84–90
  • 相对小参数指令模型：推理不需要 GPU 或权重文件；代价是覆盖面等于已写规则，启动要导入整包。作者称在 SmolTalkBench 上，用 LLM 裁判对比参考答案，胜率约 26%，与 SmolLM-360M-Instruct 相当，并经过约 1000 个智能体、5000 个版本。README.md:13–19 作者宣称，本文未复跑，也不把该数字当作产品指标。
  • 失效边界：没写过的意图会落到后备句；安全档（优先级 ≥ 9000）按仲裁器注释不会被普通让路规则翻盘，但其识别质量取决于生成出的 safety*.py，不是形式化保证。bot/modules/arbiter.py:171–171
  • 评测依赖 LLM 裁判，和人类偏好或真实任务成功率不是一回事。推断

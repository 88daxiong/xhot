ai-memory

给编程 Agent 用的跨工具长期记忆：工作过程被写成普通 Markdown 页面，换一个 CLI 或换一台电脑，也能把上次的上下文接上。

仓库 akitaonrails/ai-memory 站点 aimemory.sh 分析提交 b38c6e5（2026-11-17 10:10 北京时间） 单文件版 下载
最大亮点

多个编程 Agent 共享一份可以打开、可以 grep 的 Markdown 记忆；采集、检索和交接在默认配置下都不必调用大模型。

常见方案是把笔记锁在某个产品里，或者把对话丢进向量库。ai-memory 的内核不是向量服务，而是一棵 git 管理的 wiki：页面路径就是身份，新版本通过「取代（supersede）」接上旧版本，SQLite 只是可重建的派生索引。源码确认

一句话输入输出：输入是各 Agent 的生命周期事件（提示、工具调用、会话结束）；输出是项目 wiki 里的页面、下一次会话的有界简报，以及可领取一次的交接。

怎么用

什么情况下用

  • 你经常在 Claude Code、Codex 等工具之间切换，不想每次重新解释项目。
  • 希望记忆是普通 Markdown，能进 git、能在编辑器里打开。
  • 可以先不配大模型，只要「记下发生过什么、下次能搜到、能交接」。

什么情况下不用

  • 主要需求是给制度、合同、手册做「带引用的文档问答」——那是 WeKnora 这类知识库的事。
  • 无法保证「一个数据目录只跑一个服务器」。
  • 所用 Agent 没有可靠的会话结束钩子，又不打算手工收尾或配置空闲结束。

最小上手方案

官方推荐入口是项目站点 aimemory.sh，以及本分析提交中 README 的 Quick start。Linux / macOS 上，该文档给出的两条命令是：

curl -fsSL https://github.com/akitaonrails/ai-memory/releases/latest/download/install.sh | sh
ai-memory setup
  • 文档写明：install.sh 会按发布页的 SHA-256 校验后再安装到 ~/.local/bin/ai-memory；ai-memory setup 会创建数据目录和令牌、启动用户服务，并为它找到的 Agent 接线，先显示计划再询问。作者宣称
  • 官方验证方法：重启 Agent 后问一句 “What do you remember about this project?”，看它是否通过 ai-memory 回答。作者宣称
  • 请注意：这条官方路径安装的是 releases/latest，不一定等于本页分析的 3.4.7。若要贴近本分析，请到 GitHub Releases 查看 3.4.7 的安装说明，不要假定安装脚本还有未在文档中出现的版本参数。待验证
  • 把脚本通过管道交给 sh 是官方写法；更谨慎的做法见同一提交的 docs/install.md。本文未在本机执行安装或运行服务器。
  • Docker 快速开始在该 README 中被明确写成默认无认证，需要时再执行 ai-memory auth enable。单用户本机更适合先走上面的原生两条命令。

深入

下面这些不影响先建立整体图景。需要对照源码、字段或边界时再展开。证据仍指向固定提交。

真源、版本链和去重
  • 数据目录里，wiki/ 是 Markdown 真源，db/ 是 SQLite 派生索引。docs/ARCHITECTURE.md:36–39 README.md:739–758
  • 页面身份是 (workspace_id, project_id, path)。同一路径只有一行 is_latest=1。内容变化会把旧行降为历史，新行通过 supersedes 接上。crates/ai-memory-store/migrations/V01__init.sql:23–48
  • 正文 SHA-256 与去掉时间戳后的 frontmatter 相同，则不新建版本，只补证据。这是去重，不是删除。crates/ai-memory-store/src/ops.rs:2164–2233
  • 并发写入可用「路径尚不存在 / 最新版本仍是这个 id」的条件更新；一批里有一处不满足则全部不写。crates/ai-memory-store/src/ops.rs:305–351
检索怎么融合，以及一个容易误解的点

混合检索把全文、实体、图邻居、可选向量和观察流做 RRF（k=60）融合。若观察流已经给某篇会话页投票，该页的全文贡献会被去掉，避免标题里的词压过真正命中正文的会话。crates/ai-memory-store/src/reader.rs:8920–8950

向量路没有相似度下限。库里一旦有嵌入，向量检索几乎会对每个查询返回若干页。源码因此用「是否存在词法命中」（全文、实体或观察流）判断这是不是一次真正的匹配。crates/ai-memory-store/src/reader.rs:8913–8918

记忆如何变旧，以及「删除」到底指什么
保留分数 ≈ 显著度 · exp(−λ · 年龄) + 访问强化项 默认 λ=0.02（约 35 天半衰期），访问越多、越近，忘得越慢。

公式在 crates/ai-memory-store/src/decay.rs:92–203。压缩、去重、按层丢弃默认关闭。README 说「原件留在 git、没有硬删除」，这说的是页面整理通常不丢 git 历史；库内仍有墓碑链硬删和观察修剪，修剪后不能再重新巩固该会话。docs/ARCHITECTURE.md:263–268

失败边界与安全要点
  • 服务器饱和时钩子收到 429；会话已绑到另一 Agent 时是 409。探测工作目录有 2 秒上限，以免拖垮服务器。
  • 进入存储的文本必须经过 sanitize()。默认只绑定回环；新安装会在数据目录生成根令牌，不写进 Agent 配置。
  • 已清除的会话不能靠扫描磁盘把摘要救回索引。
  • 作者宣称写入上限约 700 次/秒，本文未复测。待验证

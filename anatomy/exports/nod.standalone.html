Nod

n8n 团队做的本机个人 Agent：它在你自己的电脑上处理真实差事——读邮件、写通话简报、在网页上取消试用——并且把「能不能做」放在服务器策略里，而不是只写进提示词。

最大亮点

政策在服务器里执行，不在提示词里商量。工具结果默认被标成不可信数据；对外发言、付款等动作先写成待批准快照，你确认后由可信 worker 按该快照执行一次。

常见的电脑使用 Agent 把「请先问我」写在系统提示里，模型一旦把网页或邮件内容当成指令，就可能越权。Nod 把批准、保险库和花费上限做成服务端状态机，并把浏览器、搜索、本地文件等工具输出用分隔符包起来再交回模型。源码确认

一句话输入输出：输入是桌面应用、Telegram 或 WhatsApp 里的一项任务；输出是沙箱或浏览器里的实际操作，以及需要你点头后才会发出去的邮件、消息或付款。电脑要保持开机，并已连接你自己的模型。

怎么用

什么情况下用

  • 希望有一个跑在自己电脑上的个人助手，能处理邮件、日历、Slack 和真实网页上的差事，并且在对外行动前先问你。
  • 可以接受自己提供模型（API 或 ChatGPT Plus/Pro 一类），并在这台机器上安装 Docker。
  • 在意密钥和卡片安全码不要进聊天、不要进沙箱；能接受应用连接默认经过 n8n 托管的连接服务。作者宣称

什么情况下不用

  • 需要笔记本合上后定时任务仍要跑。作者写明日程只在运行 Nod 的那台机器开机时执行；一直在线需要 Mac mini 或自建服务器，托管版还在路线图上。作者宣称
  • 不能接受数据经过模型供应商，或默认把基础用量分享给 n8n（设置里可关闭新的发送）。作者宣称
  • 想把它当成已经定稿的生产安全产品。仓库标注 research preview；作者写明安全检查仍是模型判断。作者宣称

最小上手方案

从 Releases 安装桌面应用（macOS 14+；Windows 11 与 Linux x64 为预览），或在已有 Node.js 24.21、pnpm 和 Docker 的机器上从源码启动。分析所用版本是 nod-v0.9.7：

git clone https://github.com/n8n-io/nod.git && cd nod
git checkout 1128fcfd770d619f3391e0bd9f1ca2f9966f2be6
corepack enable
pnpm start
  • 安装后连接你自己的模型，再连接需要的应用。作者称完整设置大约十分钟。作者宣称
  • 它不是 n8n 工作流产品里的 AI Assistant，而是同一团队做的独立应用。作者宣称
  • 本文只阅读了公开源码、compose 文件、工具定义和官方文档，没有在本机启动 Nod，也没有跑能力评测。待验证

深入

下面这些不影响先建立整体图景。需要对照源码、字段或边界时再展开。证据指向提交 1128fcf（nod-v0.9.7）。核对过的文件与该标签内容一致。

进程与容器怎么分开
  • 本机 compose.yaml 起四个角色：PostgreSQL 17、只读加固的 Chromium 浏览器容器、workspace 容器，以及一个仅有 NET_ADMIN 的 workspace-network 旁路。workspace 通过 network_mode: service:workspace-network 上网，自己不持有这张网卡。源码确认
  • 浏览器与 workspace 都 cap_drop: [ALL]、no-new-privileges；浏览器还是 read_only，数据放在 /data 卷和 tmpfs。workspace 镜像基于 Node 24，预装办公套件、ripgrep、OCR 等，默认用户是 node，工作目录 /workspace。源码确认
  • 依赖里能看到运行时选型：@earendil-works/pi-coding-agent 1.5.2、Fastify、agent-browser、Composio、Electron 桌面壳，以及 1Password SDK。源码确认
不可信数据如何进模型
  • src/runtime/untrusted.ts 的 delimit() 会中和文本，再按来源加上开闭分隔符。运行时对 browser、web_search、files、computer、codemode 以及 mcp__ 等工具结果走这条路径。源码确认
  • 这只能降低「网页或邮件把自身当成指令」的成功率，并不能证明模型永远不会越权。分隔之后，政策仍要靠下面的批准状态机来兜。推断
批准是快照，不是再问一句「可以吗」
  • createApprovals 把待确认动作写入 approvals 表。用户确认后，提示要求可信 worker 执行当时保存的那份快照一次，不得改换动作，也不得由模型自己再执行一遍。执行结果用 untrustedBlock 包回上下文。源码确认
  • 付款工具要求先填好结账页可见总额，再走私人批准；卡片安全码不在聊天里收集，由 Nod 代为提交一次。工具说明写明：卡片输入并不证明已经结算。源码确认
  • 浏览器私有配置要先经过 sign-in 信任检查才能复用已登录会话；公开页面只需打开浏览器。源码确认
记忆、禁入名单，以及仍然存在的边界
  • 记忆是一棵可开关的树：条目、归档和技能。关闭后默认不能再写入；服务把它渲染成字节，存进对象存储，带版本。源码确认
  • 用户可维护 local_keep_out 与 computer_keep_out 名单，限制本地文件和电脑使用的范围。源码确认
  • README 写明：文件、记忆和已保存登录态留在运行 Nod 的机器上；模型供应商仍会收到任务所需内容；应用连接默认走 n8n 托管的连接服务；新用户默认分享基础用量。作者还给出一组 240 次决策的模型对比数字。这些是文档主张，本文没有复现评测，也没有审计出站流量。作者宣称待验证
  • 仓库有真实 harness 上的能力评测（假应用和仿网站，调用付费模型）。单元测试不会跑它们。本文没有执行 pnpm run eval:capability。待验证
和替代方案比
  • 与 OpenAI Operator、Claude Computer Use 一类托管电脑使用相比：Nod 把运行时放在你的机器上，模型也可以自选；代价是你要维持这台机器在线，并且默认仍经过 n8n 的连接服务。推断
  • 与只提供代码沙箱的 E2B / OpenSandbox 相比：Nod 是面向个人差事的完整产品（记忆、批准、浏览器、付款、聊天通道），不是给其他 Agent 调用的通用沙箱 API。推断
  • 与 Mingle 相比：Mingle 把已有编码代理接到你正在用的 IM；Nod 自己用 Pi 跑循环，目标是替你操作邮箱、日历和网站。二者可以同时存在，但不是同一层。推断

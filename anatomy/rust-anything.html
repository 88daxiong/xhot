rust-anything

给编码代理用的渐进式 Rust 迁移夹具：它不负责把代码翻译成 Rust，而是剖出热路径、生成桥接、录下原实现行为，再用对拍门禁证明「结果没变」。

最大亮点

把「改写成 Rust」拆成一条可判定的闭环：原实现先把输入输出写成 cases.jsonl，Rust 端口必须在门禁里对上每一条，并且通过格式、警告、测试和构建，才允许说这一单元完成。

常见做法是让模型整段翻译，再靠几个手工例子冒烟。rust-anything 假定模型不可靠的是「该搬哪、行为如何对齐、怎样安全替换」，于是用分析器、桥接代码生成和录制回放来补上这些步骤。调用方在迁移过程中仍走原 API。源码确认

一句话输入输出：输入是一个仍可运行的原语言单元（可加上工作负载和补充用例）；输出是保留原 API 的桥接 crate、一份录制用例，以及一次全通过或指出失败项的 gate 报告。

怎么用

什么情况下用

  • 有一段可运行的 TypeScript/JavaScript、Python、C、Go、Ruby 或 Java 代码，想逐步换成 Rust，并且每一步都能证明行为没变。
  • 只想加速热循环，而不是一次重写整个程序。
  • 编码代理负责写 Rust，但需要外部夹具来决定搬什么、如何对齐、何时算完成。

什么情况下不用

  • 期望这个工具自动把程序翻译成 Rust——它明确不承担翻译。
  • 热点是「每次调用都很小」的函数：作者也写明，单次跨语言调用往往比 JIT 还慢，值得搬的是成批循环。
  • 类型信息不足（没有 TS 类型、Python 注解、C/Go/Java 签名或 Ruby YARD），生成用例和桥接会变差。

最小上手方案

README 建议把下面这段交给 Claude Code、Codex、Cursor 或 Gemini CLI，或自己安装：

npm install -g rust-anything
# 或：cargo install --git https://github.com/erkamyaman/rust-anything
rust-anything setup

深入

下面这些不影响先建立整体图景。需要对照源码、字段或边界时再展开。证据仍指向固定提交。

行为真源和门禁里有哪些检查
  • 录制产物是 crate 目录下的 cases.jsonl，工作文件在 .rust-anything/。src/harness.rs:20–21
  • RecordOutcome 统计总用例、错误数、陷阱用例和按函数计数；DiffOutcome 含通过/失败数、缺失导出口和首批不匹配（函数、参数、期望、实际）。src/harness.rs:62–87
  • gate 聚合：格式、clippy（警告即失败）、cargo test、带 // SAFETY: 的 unsafe、不再有 unimplemented!、构建、导出口、全部用例匹配；另会并入 error_paths::checks。全部通过才 passed。src/gate.rs:28–107
  • 工具自身的 Cargo.toml 写了 unsafe_code = "forbid"，这约束的是 rust-anything 这个 CLI，不是被迁移的 crate。被迁移 crate 允许有注释清楚的 unsafe。
各语言桥接能覆盖什么
  • README 表格（分析提交）：TS/JS 可到文件夹或文件，含 class 与 async；Python 到包或模块；C 到 .c 文件中的同名函数；Go 到包；Ruby 到模块函数；Java 到 public static 方法。除 C 外可使用 --batch，让数据留在 Rust 里批量计算。README.md:103–115
  • 类型来自源码中的类型/注解/签名；未加类型却当数字用的参数会被推断为数字。语言也可由清单文件检测，或用 --lang 覆盖。作者宣称（同表），实现分散在 src/lang/ 与各 codegen_*.rs。
  • 整应用升级还有 analyze --whole-app、app record、front-door 等另一条环，入口在 src/main.rs:184–210。本文以单单元循环为主，未完整展开整应用路径。
和替代方案比，以及失效边界
  • 相对「让模型直接重写」：多了可重复的录音和对拍，少了自动翻译。失败时你看到的是具体用例差异，而不是一段无法验证的新代码。
  • 相对手工写 FFI：桥接和包装是生成的，但仍要你保证 Rust 算法正确，并且原程序能被驱动、能导入。
  • 边界：原实现若有隐藏的全局状态、时间、随机性或未建模的副作用，录音会对不准；键顺序默认要一致（diff 可选择忽略键序）。src/harness.rs:565–572
  • FFI 开销可能让细粒度函数变慢。仓库带有 tests/loop.rs 与 demo/，但本文没有跑它们。
分析范围与未验证事项
